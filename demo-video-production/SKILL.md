# 产品功能演示视频制作

面向任何"把一套系统/产品/能力拍成可自证的演示片"的制作流程。目标产物是「真操作感、
有配音有字幕、逐点覆盖需求、格式合标」的演示视频，以及可复用的截图素材。

> 核心思想：**需求/功能清单是唯一输入，视频是它的忠实可视化**——每个要传达的点都要在
> 片里有真实画面，不能只靠口播带过。

## 工作流总览

```
1 拆解需求 → 功能清单 / 每功能必须展示的方面 / 交付硬约束
2 决策架构 → 是否有现成产品(决定做不做demo) / 数据来源 / 语音方案 / 操作感方案
3 造数据资产 → 六类仿真 + 真实素材(免费图库) + 真实感做旧
4 底座验证 → 配音(主时钟) / 帧→视频 / 字幕 / 音画合并(ffmpeg)
5 逐功能制作 → 分镜剧本 → (如无产品)做demo → 录屏脚本 → 合成(鼠标+字幕) → 成片
6 合并总片 → 片头 + 各段 + 总时长校验(<上限)
7 素材整理 → 把成片/关键帧归档为可复用的演示素材
```

**先读 `references/workflow.md` 获取各阶段详细操作。**
其余按需：
- `references/needs-parse.md` —— 需求/功能清单怎么拆
- `references/quality-gates.md` —— 每段成片的验收关卡
- `references/pitfalls.md` —— 高频坑与解法（windows 尤其相关）
- `templates/` —— 录屏/合成/分镜/过渡页骨架 + 坐标探测

## 铁律（跨项目不变）

### 1. 真实感 > 花哨（最容易被挑刺的点）
- 界面数据用**真实来源**（免费图库照片 + 做旧，如监控 OSD）而非纯程序画占位
- 演示内容**与提示词/口播一致**（说"黄帽"画面就真是黄帽）
- **标注/识别框必须真实贴合目标，绝不悬空、错位、虚构**
- 涉及内容真实性的改动，先出**预览图确认，通过再改视频**

### 2. 配音是主时钟，画面跟着声音走
先写旁白、先生成配音并实测每句时长，再据它排镜头时长。音画天然同步、总时长可控。

### 3. 覆盖每个要传达的点
需求/功能清单要求展示几个方面，就必须演示几个方面，且都有真实画面，不能只口播带过。

### 4. 操作真实感
叠加合成鼠标(光标+点击脉冲)让静止镜头片像真实操作录屏；点击位置用真实坐标探测，精准
落在按钮上；封面/过渡页**不叠加鼠标**。

## 执行原则

- **先预览后成片**：涉及内容真实性的节段先出预览确认。
- **先打通再量产**：先做一条成片跑通全链路，再批量做其余。
- **可复现**：每段做成「分镜 + 录屏脚本 + 合成配置」，能重跑。
- **留备份**：改已有文件前先复制备份。
- **人工确认优先**：关键步骤(数据真实性、标注贴合、关键界面)默认需人工确认；
  **全自动仅在用户明确要求时运行**，且会跳过/标注需人工复核的环节。

## demo 制作(决定路径)

- **已有现成产品**：直接对真实页面/系统录屏，跳过 demo。
- **无现成产品**：先做 **静态演示页 demo** —— 用 HTML/CSS 搭与目标产品一致的高保真界面，
  配**程序化数据 + 浏览器自动化**驱动交互，再录制。这样"演示的是产品应有形态"，无需真后端。
- demo 与真实产品的差别要跟用户对齐，避免被误认为生产系统。

## 边角情况

- 某点无专属界面：优先用 demo 已有页面真实渲染截图，别硬凑别的图(会"文不对图")。
- 需要真实图片但无下载权限：本地闲置照片 + 做旧优先于上网或付费。
- 总时长超限：砍片头、压缩过渡页停留、合并表达，优先保重点功能。
- 平台无关性：本流程依赖"浏览器自动化/系统TTS/ffmpeg"等通用能力，不绑定专有工具。
