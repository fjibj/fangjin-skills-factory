# 全流程操作步骤

> 每一步给出目标、做法、产出与注意事项。脚本骨架在 `templates/`，改占位符即可。
> 「演示系统/页面」指功能页面(demo)；「制作工作区」指独立于演示页的制作目录。

## 0. 前置：建立工作区与底座自检

```
工作区/
├─ transitions/    过渡页 + 片头(html)
├─ scripts/        生成器/录屏/合成/合并 (js+py)
├─ assets/         数据素材
├─ out/
│   ├─ clips/      words.json + cn_NN.wav (配音)
│   ├─ frames/<功能>/  关键帧(裸帧无字幕)
│   └─ final/      <功能>_final.mp4 + total_final.mp4
└─ storyboard.md   分镜剧本
```

**底座自检(新环境一次性，见 `pitfalls.md`)**
1. 中文配音可用（系统 TTS）
2. 帧→MP4 可写读（OpenCV）
3. ffmpeg 可用（合成音视频）
4. 浏览器自动化可截图（系统 Chrome，headless）

## 1. 拆解需求（见 `needs-parse.md`）

产出一张「功能 × 展示方面」对照表 + 交付硬约束。写进 `storyboard.md` 当作验收基准。

## 2. 规划演示架构

- 每个功能单独成片再合并，便于分散控制权重、单独重录。
- 决定是否需要做 demo（无现成产品才做）。
- 为每个功能准备**过渡页**(标题 + 一句话说明 + 序号)。
- 设计分镜剧本 `storyboard.md`：每功能旁白逐字稿 + 画面动作 + 目标时长(按语速≈4.8字/s估)。
- 决定片头(标题 + 功能总览 + 开场旁白)。

## 3. 数据素材

脚本骨架见 `templates/gen_template.py`。要点：
- 非照片类(文本/时序/音频/视频/多模态)可程序化生成。
- **照片类必须真实**：优先免费图库(如 Pixabay，可商用免署名)真实照片 + 做旧
  (时间戳/噪声/JPEG压缩/暗角)，让它像系统真实采集/监控画面。
- 类别语义要准：演示"车辆"就是目标对象，不是泛义；演示"机柜"就不是机房。
- 素材统一复制到演示系统 `assets/data/` 供页面引用。

## 4. 底座验证

### 配音(主时钟)
- 从分镜抽旁白 → TTS 生成 `cn_NN.wav`，同时输出 `words.json`(含每句实测时长)。
- **语音基本配置（默认）**：edge-tts `zh-CN-XiaoxiaoNeural`（晓晓，女声），语速 `rate=-4%`；
  中文自然度明显优于 Windows 系统 TTS（Huihui），新项目默认采用；环境无 edge-tts 时回退系统 TTS。
- 语速取自然(≈4.8字/s)，可微调；单段 60~90s 较紧凑耐看。

### 帧→视频(无声音轨)
`make_mp4(frames_dir, out, fps, timeline)`：镜头表 `[{img, sec, text}]` = 每镜头指定
图片重复 sec 秒 + 底部烧字幕。
- 字幕：**无背景块；黑字(≈#080808) + 白描边(3px)**，画在画面**底部留白区**，不遮挡主要内容。
- 中文路径：读 `np.fromfile+imdecode`，写 `cv2.imencode+np.tofile`。

### 音画合并
用 ffmpeg：`-map 0:v -map 1:a -c:v libx264 -c:a aac -shortest`。
- `-shortest` 让时长裁到较短流，保证尾部对齐。
- 合并前显式删旧文件，避免缓存污染。

## 5. 逐功能制作

每段一条重复此循环：
1. **过渡页**：新建 `transitions/tXX_功能.html`。
2. **页面(如无产品)**：做静态演示页 demo + 程序化数据；**如有产品**直接用真实页面。
   - 把占位(SVG/假数据)换成真实素材；改后用视觉核验确认。
3. **录屏**(`templates/record_template.js`)：
   - 每次操作后截图存帧 `frame_NNNNN_描述.png`
   - headless 不能真实选文件 → `window.onFiles({length:0})` 触发页面预置数据
   - 切换"数据类型/配置项"用点击触发真实 change 事件
   - 动画等待足够(约 4s)再截结果帧
   - **覆盖该功能要求展示的全部方面**
4. **配音**：分镜旁白 → TTS。
5. **合成+鼠标**(`templates/mux_template.py`)：镜头表 + 字幕 + 鼠标时间线 + 配音。
   - 鼠标坐标用浏览器 `boundingBox` 实测(`templates/probe_template.js`)；封面/过渡页不加鼠标。
   - **鼠标 = 真人运动学重放(默认)**：点击点之间自动滑行(smoothstep 加减速，时长随距离
     180~480ms) → 到位悬停 170~260ms(不等长更自然) → 按下仅 1~2px 微沉 100~130ms，
     无光圈无阴影；操作结束后停留约 1s 再 200~300ms 淡出——光标别钉死在按钮上直到切镜。
     入画起点取上一镜头末光标位置(镜头间连续)，首个镜头从目标左下方滑入。
   - **关键点击加强调光圈(可选)**：仅对真正要引导视线的动作标 `key`，画大光圈渐隐
     250~400ms 强调；**绝不做成每次点击都闪**。录屏动作若全是 80ms 连击(capture 时
     clk 之间没留间隔)，可接受快速连点观感，但想更真人需在录屏脚本里给点击间隔留 300ms+。
6. **成片 + 验收**：过 `quality-gates.md` 全部关卡，出预览确认(如需)再交付。

## 6. 合并总片

- 片头：深色底 + 标题/副标题 + 功能模块总览 + 开场旁白(带字幕，无鼠标)。
- 各段参数统一(编码/采样率/声道)；concat。
- **总时长校验**：必须 < 上限(常规 10 分钟)。超则压缩过渡页/片头/合并表达。

产出 时间段×功能 对照表（供后续文档/素材使用）。

## 7. 素材整理

- 把成片时间段表 + 关键帧截图(用裸帧，无字幕)归档，供文档插入或演示引用。
- 无专属界面的节段：补做一张风格统一的界面图，而非硬凑别的图。
